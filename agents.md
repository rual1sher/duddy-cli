# 🤖 Duddy — Документация для AI-агентов и разработчиков

> **Duddy** — это легковесный, высокоэффективный консольный AI-ассистент и автономный агент для Linux и DevOps, написанный на Node.js. Он работает через OpenRouter API (поддерживая как бесплатные модели, так и флагманы вроде Gemini 3.8 Flash, Claude 3.7 Sonnet, GPT-4o) и умеет напрямую взаимодействовать с файловой системой проекта.

---

## 🛠️ Технологический стек

* **Среда выполнения:** Node.js (версия >= 18.0.0, нативная поддержка ES Modules `"type": "module"`).
* **AI Provider / SDK:** `openai` SDK (`baseURL: 'https://openrouter.ai/api/v1'`) с поддержкой Function Calling (Tool Calling), стриминга ответов и отслеживания reasoning-токенов.
* **Терминальный интерфейс (CLI & TUI):**
  * `chalk` (v6+) — стилизация и цветной вывод в ANSI.
  * `ora` (v9+) — анимированные спиннеры ожидания и рассуждений.
  * `@inquirer/prompts` — интерактивные меню, селекторы моделей и подтверждения.
  * Нативный модуль `node:readline` — интерактивная командная строка с автодополнением по `Tab`.
* **Файловая система:** Нативные `node:fs/promises`, `node:fs`, `node:path`.
* **Стандарты конфигурации:** Linux XDG Base Directory (`~/.config/duddy/config.json`).

### Схема работы агентного цикла (Agent Loop)

```
[ Пользовательский ввод ] 
          │
          ▼
   [ src/repl.js ] ──► Формирует messagesToSend (system + history + user)
          │
          ▼
   [ src/api.js ] ──► Запрос в OpenRouter API (streamChatCompletion + AGENT_TOOLS)
          │
     ┌────┴─────────────────────────────┐
     │                                  │
     ▼ (tool_calls)                     ▼ (content)
[ Исполнение инструментов ]       [ src/formatter.js ] ──► Вывод в терминал
   [ src/tools.js ]                     │
     │                                  ▼
     ├─► Автономное исполнение     [ Завершение хода ]
     │   fs.writeFile / readFile / etc.
     │
     ▼
[ Возврат результата (role: 'tool') ]
     │
     └────► Повторный виток цикла в API ──► Модель формирует финальный ответ
```

## ⚙️ Система инструментов (Tool Calling)

Duddy поддерживает автономное выполнение операций с файловой системой. Все действия выполняются напрямую без блокирующих подтверждений:

| Инструмент | Параметры | Описание | Режим |
| :--- | :--- | :--- | :--- |
| `create_file` | `path`, `content` | Создает новый файл или перезаписывает существующий (автоматически создавая папки). Защищен от передачи пути к папкам (`EISDIR`). | Автономно |
| `create_folder` | `path` | Создает папку (включая все промежуточные подпапки `recursive: true`). | Автономно |
| `read_file` | `path` | Читает текстовое содержимое файла. Ограничен 40 000 символов для защиты от раздувания контекста. Возвращает чистый текст без JSON-экранирования. | Автономно |
| `edit_file` | `path`, `old_content`, `new_content` | Точечно заменяет фрагмент `old_content` на `new_content` в существующем файле. | Автономно |
| `delete_file` | `path` | Удаляет файл из файловой системы. | Автономно |
| `delete_folder` | `path` | Рекурсивно удаляет папку со всем содержимым (защищен от удаления корня `.`). | Автономно |
| `list_dir` | `path` (опц.) | Возвращает список файлов и директорий с иконками 📁/📄. | Автономно |

### Принцип автономности
* Все операции (`create_file`, `create_folder`, `edit_file`, `delete_file`, `delete_folder`, `read_file`, `list_dir`) исполняются сразу по запросу модели.
* Результат выполнения (успех или ошибка) немедленно отображается в консоли и возвращается в контекст агента.

## 📜 Общие правила и соглашения разработки

### 1. Экономия токенов и управление контекстом
* **Никакой воды и приветствий:** Системный промпт (`DEFAULT_SYSTEM_PROMPT` в [`src/config.js`](file:///home/rualisher/Projects/duddy/src/config.js)) запрещает модели использовать вступительные и заключительные фразы ("Конечно!", "Вот ваше решение:", "Надеюсь, это помогло!").
* **Сжатый вывод результатов инструментов:** Инструменты возвращают понятный модели чистый текст (plain text), а не многократно экранированный JSON, экономя токены промпта.
* **Ограничение истории:** В `src/repl.js` хранится скользящее окно последних 20 сообщений (`session.messages.slice(-20)`), предотвращая бесконтрольный рост затрат.
* **Мониторинг лимитов:** Команда `/usage` выводит точный процент заполнения контекстного окна текущей модели (`contextLength - lastTokens`), остаток дневных бесплатных запросов и расход средств.

### 2. Безопасность файловых операций
* Все пути нормализуются через `path.resolve(process.cwd(), targetPath)`.
* Запрещено удалять корень проекта (`process.cwd()`).
* При создании файлов проверяется, не является ли целевой путь уже существующей директорией (`EISDIR`).
* Чтение файлов лимитировано (`MAX_CHARS = 40000`), чтобы исключить вылет по переполнению контекста модели.

### 3. Обработка потокового вывода и рассуждений (Reasoning)
* Модели с длинной цепочкой рассуждений (DeepSeek R1, Nemotron и др.) передают свои мысли либо в `delta.reasoning`, либо внутри тегов `<think>...</think>`.
* Во время рассуждений спиннер не должен гаснуть; он отображает `Duddy рассуждает... (reasoning)`.
* Теги `<think>` обрабатываются через скользящий буфер (`thinkBuffer`), исключающий зависание в случае, если закрывающий тег `</think>` разделен сетью между чанками.
* Заголовок ответа `╭─ ✦ Duddy` печатается только при поступлении первого значащего (непустого) символа ответа.

### 4. Стандарты добавления новых команд
* Все новые слеш-команды должны быть зарегистрированы в массиве `AVAILABLE_COMMANDS` в [`src/commands.js`](file:///home/rualisher/Projects/duddy/src/commands.js).
* Обработчик команды добавляется в `switch (cmd.toLowerCase())` в [`src/repl.js`](file:///home/rualisher/Projects/duddy/src/repl.js).
* Команды должны поддерживать быстрый выход по `Esc` без падения процесса.
