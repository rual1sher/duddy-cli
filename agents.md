# 🤖 Duddy — Документация для AI-агентов и разработчиков

> **Duddy** — это легковесный, высокоэффективный консольный AI-ассистент и автономный агент для Linux и DevOps, написанный на Node.js. Он работает через OpenRouter API и Google AI Studio (Gemini API напрямую, поддерживая как бесплатные модели, так и коммерческие флагманы вроде Gemini 3.8 Flash, Claude Sonnet 4.6, GPT-4.1) и умеет напрямую взаимодействовать с файловой системой проекта.

---

## 🛠️ Технологический стек

* **Среда выполнения:** Node.js (версия >= 22.0.0, нативная поддержка ES Modules `"type": "module"`).
* **AI Provider / SDK:** `openai` SDK (`baseURL`: OpenRouter `https://openrouter.ai/api/v1` или Google AI Studio `https://generativelanguage.googleapis.com/v1beta/openai/`) с поддержкой Function Calling (Tool Calling), стриминга ответов и отслеживания reasoning-токенов.
* **Терминальный интерфейс (CLI & TUI):**
  * `ink` (v8+) и `react` (v19+) — современный реактивный консольный интерфейс (TUI в стиле Claude Code).
  * `ink-text-input` (v6+) — поле ввода текста и скрытых ключей.
  * `chalk` (v6+) — стилизация и цветной ANSI-вывод.
  * `ora` (v9+) — спиннер для разового (one-shot / pipe) режима.
* **Файловая система:** Нативные `node:fs/promises`, `node:fs`, `node:path`.
* **Стандарты конфигурации:** Linux XDG Base Directory (`~/.config/duddy/config.json`).

## 🏗️ Архитектура проекта

### Архитектура вывода и событий:
Ядро агента полностью отделено от интерфейса: `runAgentTurn` в `src/agent.js` принимает сообщения и `toolCtx`, исполняет цикл взаимодействия с LLM и отправляет типизированные события (`onPhase`, `onModel`, `onText`, `onStepEnd`, `onToolStart`, `onToolResult`, `onWarning`). В интерактивном режиме эти события принимает реактивный компонент `src/ui/App.js` на базе Ink, обновляя состояние TUI, стримя текст и показывая модальные оверлеи (Picker, Approval, SecretInput, BrowserLogin). В неинтерактивном разовом или пайплайн-режиме (`bin/duddy.js`) события обрабатывает `src/plainRenderer.js` с прямым потоковым выводом в `process.stdout` без запуска React/Ink.

### Схема работы агентного цикла (Agent Loop)

```
[ Пользовательский ввод ] 
          │
          ▼
    [ src/ui/App.js ] ──► Формирует messagesToSend (system + history + user)
          │
          ▼
   [ src/agent.js ] ──► Запрос в LLM API (streamChatCompletion + AGENT_TOOLS)
          │
     ┌────┴─────────────────────────────┐
     │                                  │
     ▼ (tool_calls)                     ▼ (content)
[ Исполнение инструментов ]       [ events.onText ] ──► Живой стриминг в TUI / plainRenderer
   [ src/tools.js ]                     │
     │                                  ▼
     ├─► ctx.approve / автоподтверждение [ events.onStepEnd / Завершение хода ]
     │   fs.writeFile / readFile / etc.
     │
     ▼
[ Возврат результата (role: 'tool') ]
     │
     └────► Повторный виток цикла в API ──► Модель формирует финальный ответ
```

## ⚙️ Система инструментов (Tool Calling)

Duddy поддерживает выполнение операций с файловой системой в раздельных режимах безопасности: безопасные операции чтения и структуры выполняются автономно, а операции записи и удаления требуют подтверждения пользователя:

| Инструмент | Параметры | Описание | Режим |
| :--- | :--- | :--- | :--- |
| `create_file` | `path`, `content` | Создает новый файл или перезаписывает существующий (автоматически создавая папки). Защищен от передачи пути к папкам (`EISDIR`). Перед запросом подтверждения выводит статус и размер. | Подтверждение |
| `create_folder` | `path` | Создает папку (включая все промежуточные подпапки `recursive: true`). | Автономно |
| `read_file` | `path` | Читает текстовое содержимое файла. Ограничен 40 000 символов для защиты от раздувания контекста. Возвращает чистый текст без JSON-экранирования. | Автономно |
| `edit_file` | `path`, `old_content`, `new_content` | Точечно заменяет фрагмент `old_content` на `new_content` в существующем файле. Перед запросом подтверждения выводит дифф (до 12 строк). | Подтверждение |
| `delete_file` | `path` | Удаляет файл из файловой системы. Символические ссылки удаляются без разыменования целевого файла (`followFinalSymlink: false`). | Подтверждение |
| `delete_folder` | `path` | Рекурсивно удаляет папку со всем содержимым (защищен от удаления корня `.`, отклоняет удаление симлинков). Перед подтверждением выводит число элементов. | Подтверждение |
| `list_dir` | `path` (опц.) | Возвращает список файлов и директорий с иконками 📁/📄. | Автономно |

### Принцип автономности и подтверждения
* Безопасные операции (`create_folder`, `read_file`, `list_dir`) исполняются автономно по запросу модели.
* Опасные операции модификации и удаления (`create_file`, `edit_file`, `delete_file`, `delete_folder`) требуют подтверждения пользователя через интерактивный диалог (`Да`, `Да, и не спрашивать до конца сессии`, `Нет` — горячие клавиши `y` / `a` / `n` / `Esc`).
* В неинтерактивном окружении (без TTY или в пайпе) при отсутствии флага `--yes` опасные действия автоматически отклоняются с предупреждением.
* Флаг `-y, --yes` включает сквозное автоподтверждение (`autoApprove: true`) без остановок на диалоги.
* Результат выполнения (успех, отмена пользователем или ошибка) немедленно отображается в консоли и возвращается в контекст агента.

## 📜 Общие правила и соглашения разработки

### 1. Экономия токенов и управление контекстом
* **Никакой воды и приветствий:** Системный промпт (`DEFAULT_SYSTEM_PROMPT` в [`src/config.js`](src/config.js)) запрещает модели использовать вступительные и заключительные фразы ("Конечно!", "Вот ваше решение:", "Надеюсь, это помогло!").
* **Автоматическая адаптация стиля:** Стиль ответа выбирается моделью автоматически (ADAPTIVE MODE в `DEFAULT_SYSTEM_PROMPT`), системный промпт не хранится в конфиге.
* **Сжатый вывод результатов инструментов:** Инструменты возвращают понятный модели чистый текст (plain text), а не многократно экранированный JSON, экономя токены промпта.
* **Ограничение истории:** В `src/history.js` хранится история последних 10 ходов пользователя (`MAX_HISTORY_TURNS = 10`), что гарантирует сохранение контекста вызова инструментов и не разрывает пары assistant.tool_calls ↔ tool. Для предотвращения раздувания контекста результаты `tool` из предыдущих ходов длиннее 4000 символов обрезаются до 4000 символов с пометкой об обрезке.
* **Мониторинг лимитов:** Команда `/usage` выводит точный процент заполнения контекстного окна текущей модели (`contextLength - lastTokens`), остаток дневных бесплатных запросов и расход средств.

### 2. Безопасность файловых операций
* **Ограничение рабочей папкой:** Все пути проверяются через асинхронную функцию `resolveSafePath(targetPath, { followFinalSymlink })` относительно канонического корня проекта (`await fs.realpath(process.cwd())`).
* **Защита от Directory Traversal и побега через симлинки:** Определяется реальный путь (`fs.realpath`) ближайшего существующего предка и проверяется, что итоговый путь не выходит за пределы `root`. Выход за пределы рабочей папки блокируется ошибкой доступа.
* **Обработка симлинков:**
  * Для операций удаления (`delete_file`, `delete_folder`) параметр `followFinalSymlink` отключен (`false`): для проверки берется `realpath` родителя + `basename`, что позволяет безопасно удалять сам симлинк без разыменования целевого файла.
  * Для `delete_folder` действует строгий запрет на удаление корня (`relPath === '.'`), а при обнаружении симлинка через `fs.lstat` операция отклоняется с требованием удалить ссылку через `delete_file`.
* **Валидация перед подтверждением:** Запрос подтверждения у пользователя (`requestApproval`) вызывается строго после всех проверок валидности (существование, соответствие типа папка/файл, успешное нахождение заменяемого блока через `fuzzyReplace`), но до физической записи на диск.
* **Безопасность конфигурации:** Директория `~/.config/duddy` создается с правами `0o700`, а файл `config.json` сохраняется и проверяется с правами `0o600` (защита API-ключа от несанкционированного чтения другими пользователями системы).
* **Лимит чтения:** Чтение файлов лимитировано (`MAX_CHARS = 40000`), чтобы исключить вылет по переполнению контекста модели.

### 3. Обработка потокового вывода и рассуждений (Reasoning)
* Модели с длинной цепочкой рассуждений (DeepSeek R1, Nemotron и др.) передают свои мысли либо в `delta.reasoning`, либо внутри тегов `<think>...</think>`.
* Во время рассуждений спиннер не должен гаснуть; он отображает `Duddy рассуждает... (reasoning)`.
* Теги `<think>` обрабатываются через скользящий буфер (`thinkBuffer`), исключающий зависание в случае, если закрывающий тег `</think>` разделен сетью между чанками.
* Заголовок ответа `╭─ ✦ Duddy` печатается только при поступлении первого значащего (непустого) символа ответа.

### 4. Стандарты добавления новых команд
* Все новые слеш-команды регистрируются в массиве `AVAILABLE_COMMANDS` в [`src/session-actions.js`](src/session-actions.js).
* Обработчик команды добавляется в `handleCommand` в [`src/ui/App.js`](src/ui/App.js).
* Команды поддерживают быстрый выход по `Esc` без падения процесса.

### 5. Архитектура провайдеров AI (src/providers.js)
* **Мультипровайдерность:** Duddy поддерживает OpenRouter и Google AI Studio напрямую через OpenAI-совместимый API (`v1beta/openai/`).
* **Конфигурация:** В `PROVIDERS` описаны параметры каждого провайдера: `baseURL`, заголовки, поля ключа в конфиге (`apiKey`, `googleApiKey`) и переменные окружения (`OPENROUTER_API_KEY`, `GEMINI_API_KEY`, `GOOGLE_API_KEY`).
* **Приоритет ключей:** `getProviderKey` сначала проверяет переменные окружения провайдера, затем поле в `config.json`.
* **Автоопределение:** Функция `detectProviderForModel` определяет провайдера по названию модели (модели, начинающиеся с `gemini-` или `gemma-` без `/`, направляются в Google AI Studio).
* **Смена провайдера:** При переключении модели или авторизации обновляются `session.provider`, `session.apiKey` и сохраняются в `config.json`.
